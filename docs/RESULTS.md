# Experimental Results

## 1. Overview

This document summarizes the experimental results of the
Construction Safety Risk Predictor project.

The objective is to evaluate how accurately supervised machine-learning
models can reproduce worker safety decisions generated by a stochastic
agent-based construction safety simulation.

Three classifier families were evaluated:

- Logistic Regression
- Random Forest
- XGBoost

Model selection was performed exclusively on validation simulation runs.

The selected model was then evaluated on a completely held-out set of
simulation runs that was not used during model training, model selection,
or threshold optimization.

---

## 2. Dataset

The complete synthetic dataset contains:

```text
1,000,000 worker-decision records
```

The data was generated using:

```text
100 independent simulation runs
100 workers per run
100 simulated days per run
```

Therefore:

```text
100 runs × 100 workers × 100 days = 1,000,000 records
```

The target variable is:

```text
behavior
```

where:

```text
0 = unsafe behavior
1 = safe behavior
```

The dataset contains 11 production features:

```text
SA
SK
SN
BA
PBC
reference_point
alpha
beta
lam
intention
day
```

The identifiers:

```text
run_id
seed
worker_id
```

are retained for simulation bookkeeping but are not used as model
features.

---

## 3. Leakage-Safe Dataset Split

The dataset is not split randomly by individual rows.

Instead, complete simulation runs are assigned to train, validation,
and test partitions.

This prevents observations generated by the same stochastic simulation
run from appearing in multiple partitions.

The split is:

| Partition | Simulation Runs | Records |
|---|---:|---:|
| Training | 80 | 800,000 |
| Validation | 10 | 100,000 |
| Test | 10 | 100,000 |
| **Total** | **100** | **1,000,000** |

The held-out test set remains untouched until final model evaluation.

---

## 4. Candidate Models

Three supervised classifiers were compared.

### Logistic Regression

Logistic Regression provides a simple linear baseline.

It is useful for determining how much of the simulated safety behavior
can be reproduced using approximately linear decision boundaries.

### Random Forest

Random Forest introduces nonlinear decision boundaries and interactions
between worker-state variables.

### XGBoost

XGBoost provides gradient-boosted decision trees and can model complex
nonlinear relationships between behavioral variables.

All candidate models are trained on the same training simulations and
evaluated on the same validation simulations.

---

## 5. Model Selection

The primary model-selection metric is:

```text
Macro F1
```

Macro F1 gives equal importance to both classes and is therefore more
appropriate than accuracy alone for this problem.

The validation results were:

| Model | Validation Macro F1 |
|---|---:|
| Logistic Regression | 0.6074 |
| Random Forest | 0.6114 |
| XGBoost | **0.6126** |

XGBoost achieved the highest validation Macro F1 and was selected as
the production model.

The selection decision was made before evaluating the held-out test
partition.

---

## 6. XGBoost Validation Metrics

Before threshold optimization, the selected XGBoost model produced the
following validation metrics:

| Metric | Value |
|---|---:|
| Accuracy | 0.7370 |
| Macro F1 | 0.6126 |
| Safe F1 | 0.8321 |
| Unsafe F1 | 0.3931 |
| Unsafe Recall | 0.2716 |
| ROC-AUC | 0.7152 |

These results show that the classification problem is not perfectly
deterministic.

This is expected because the underlying agent-based simulation contains
stochastic worker behavior.

---

## 7. Decision Threshold Optimization

The classifier produces:

```text
P(safe)
```

rather than directly producing the final operational decision.

A default binary classifier typically uses:

```text
threshold = 0.50
```

However, the production threshold was optimized using only the
validation partition.

The selected threshold was:

```text
0.640
```

The decision rule is therefore:

```text
P(safe) >= 0.640  -> safe
P(safe) <  0.640  -> unsafe
```

The threshold was selected to maximize validation Macro F1.

### Validation threshold comparison

| Metric | Threshold 0.50 | Threshold 0.64 |
|---|---:|---:|
| Macro F1 | 0.6126 | **0.6513** |
| Unsafe Recall | 0.2716 | **0.4892** |

Increasing the threshold substantially improves detection of unsafe
behavior while also improving overall class-balanced performance.

## 8. Final Held-Out Test Results

After model selection and threshold optimization were complete, the

The final test metrics at the default threshold of 0.50 were:

| Metric | Test Value |
|---|---:|
| Accuracy | 0.7578 |
| Balanced Accuracy | 0.6177 |
| Safe Precision | 0.7628 |
| Safe Recall | 0.9547 |
| Safe F1 | 0.8480 |
| Unsafe Precision | 0.7190 |
| Unsafe Recall | 0.2807 |
| Unsafe F1 | 0.4037 |
| Macro F1 | 0.6259 |
| ROC-AUC | 0.7235 |

These metrics describe predictive performance on simulation runs that
were never used during training or model selection.

---

## 9. Production-Threshold Test Results

The production classifier does not use the default threshold of 0.50.

It uses the validation-selected threshold:

```text
0.640
```

When the previously selected threshold is applied to the held-out test
partition:

| Metric | Threshold 0.50 | Production Threshold 0.64 |
|---|---:|---:|
| Macro F1 | 0.6259 | **0.6652** |
| Unsafe Recall | 0.2807 | **0.5011** |

This is particularly important for a safety-oriented system.

The optimized threshold nearly doubles recall for unsafe behavior while
also improving Macro F1.

No test-set information was used to choose the threshold.

---

## 10. Interpretation of Accuracy

The final observed test accuracy is:

```text
75.78%
```

This should not be interpreted as poor performance without considering
the stochastic nature of the source simulation.

The agent-based model does not generate behavior using a deterministic
rule.

For a given worker state, the underlying behavioral mechanism generates
a probability of safe behavior and then samples the actual decision.

Conceptually:

```text
worker state
     |
     v
P(safe)
     |
     v
random stochastic draw
     |
     v
observed behavior
```

As a result, identical or very similar feature vectors can legitimately
produce different target labels.

A machine-learning model cannot perfectly predict randomness that is not
encoded in its input features.

---

## 11. Stochastic Oracle Analysis

To estimate the amount of irreducible uncertainty in the task, the
project also evaluates the probability-generating mechanism of the
simulation itself.

The stochastic-oracle analysis produced approximately:

| Metric | Value |
|---|---:|
| Oracle ROC-AUC | 0.7247 |
| Observed Oracle Accuracy | 0.7591 |

The trained XGBoost test ROC-AUC is:

```text
0.7235
```

compared with an oracle ROC-AUC of approximately:

```text
0.7247
```

This indicates that the surrogate model captures most of the predictable
signal available in the simulated worker state.

The small difference between the model and the stochastic oracle is more
informative than comparing the classifier to a theoretical 100%
accuracy target.

---

## 12. Why Accuracy Is Not the Primary Metric

Accuracy can be misleading in safety classification because the safe
class occurs more frequently than the unsafe class.

For this reason, the project reports:

- Macro F1
- class-specific precision
- class-specific recall
- class-specific F1
- balanced accuracy
- ROC-AUC

The production threshold is optimized using Macro F1 rather than raw
accuracy.

This explicitly balances performance across safe and unsafe worker
behavior.

---

## 13. Unsafe Behavior Detection

Unsafe behavior is the operationally important class.

At the default threshold:

```text
Unsafe Recall = 0.2807
```

After validation-based threshold optimization:

```text
Unsafe Recall = 0.5011
```

This means that changing the decision threshold allows the production
system to identify substantially more unsafe decisions.

The improvement is achieved without retraining the underlying model.

## 20. Main Experimental Conclusion

The experiment demonstrates that a supervised machine-learning surrogate
can reproduce most of the predictable structure of worker safety
behavior generated by the stochastic agent-based simulation.

The main final results are:

```text
Selected model:             XGBoost
Validation Macro F1:        0.6126
Default-threshold Test F1:  0.6259
Production-threshold F1:    0.6652
Test ROC-AUC:               0.7235
Oracle ROC-AUC:             0.7247
Production threshold:       0.640
Unsafe recall at 0.50:      0.2807
Unsafe recall at 0.64:      0.5011
```

The proximity of the trained model ROC-AUC to the stochastic-oracle
ROC-AUC suggests that model performance is primarily constrained by the
irreducible randomness of the source behavioral simulation rather than
by a major failure of the machine-learning model.

This distinction is essential when interpreting performance on
synthetically generated stochastic labels.
